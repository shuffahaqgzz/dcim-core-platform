# phase2-closure-phase3-start - Work Plan

## TL;DR (For humans)

**What you'll get:** Phase 2 formally closed with its deferred capabilities delivered (events flow through Kafka, event-to-dashboard speed is measured against the 5-second target, and the NOC view is a live service instead of a static file), plus the first five real application services running and smoke-tested on the Development environment.

**Why this approach:** Governance hygiene and independent verification close Phase 2 honestly; the five services are built minimal-but-real on the accepted technology decisions, with database access split into per-service roles so nothing needs rework later.

**What it will NOT do:** No user-facing web dashboard, no connection to real office or production equipment, and no automatic actions on infrastructure — drafts and simulations only.

**Effort:** XL
**Risk:** Medium - many moving parts must land together (policy gates, images, services), mitigated by strict wave ordering and agent-executed verification at every step.
**Decisions to sanity-check:** one shared local services image (source mounted read-only) instead of five baked images; aggregate resource cap raised to 20 CPU / 40 GiB with documented headroom; the dual-homed-network rule gets a documented owner-approved amendment covering the five services; PR #19 closed rather than merged; services protected by one shared internal token (full identity model comes later).

13. Analytics service: read-only health/freshness/capacity/quality endpoints on the `phase2` schema as `dcim_analytics_ro`.
14. Workflow service: draft/simulate-approval endpoints only as `dcim_workflow_rw`; migration `m0004` (`phase2.workflow_drafts` + workflow role/grants); AST-level negative tests proving no execution capability.
