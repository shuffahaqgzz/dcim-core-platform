# phase2-p1-p2-vertical-slice - Work Plan

## TL;DR (For humans)

**What you'll get:** The platform's first real data path, proven end-to-end with synthetic data: a server-health (P1) and a network-utilization (P2) signal flow from fixture files through validation, explicit accept/quarantine/duplicate decisions, deterministic device identity, into PostgreSQL — and a generated static NOC view read only from the database. Plus a new `phase2-check` quality gate in CI and a public evidence document closing identity-collision condition C-06.

**Why this approach:** Batch pipeline instead of services/Kafka — issue #21 forbids long-running Phase 2 services, so one-shot script runs give the same proof (zero silent loss, determinism, idempotency) with far less machinery. Duplicate handling becomes a first-class schema value (owner-approved) because the issue demands explicit duplicate marking and the current schema cannot express it.

**What it will NOT do:** No live device connections, no writes to any infrastructure, no Kafka, no running services, no dashboard app, no latency claims, no Production/DEV-APPROVED claim.

**Effort:** Large
**Risk:** Medium - new PostgreSQL schema/migrations and a new CI gate on a repo with a strict public-safety boundary; mitigated by small per-todo PRs and retained Phase 0/1 gates.
**Decisions to sanity-check:** P1+P2 scope supersedes the earlier Q10 P1-only freeze (your call, recorded); `duplicate` added to the canonical schema (needs ADR-0027); one new pinned dependency (pydantic) required only by the new Phase 2 gate.
